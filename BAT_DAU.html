Cài đặt và nhân bản KSNK Ngoại khoa

GitHub giữ mã nguồn. Vercel chạy giao diện và API. Supabase lưu tài khoản, công việc, tin nhắn và ảnh. Mỗi bản sao dùng một dự án Vercel và một dự án Supabase riêng.

Giải nén ZIP. Thư mục chứa package.json là thư mục gốc để đưa lên GitHub và triển khai trên Vercel.

Đang nâng cấp trang đang dùng? Mở NANG_CAP_TAI_CHO.md để xem tập lệnh nâng cấp và hướng dẫn nối danh mục nhân viên hiện tại.

1. Tạo cơ sở dữ liệu Supabase

  1. Đăng nhập Supabase, chọn New project. Đặt tên dễ phân biệt với hệ thống đang hoạt động. Lưu mật khẩu cơ sở dữ liệu ở nơi riêng.
  2. Trong dự án vừa tạo, mở SQL Editor → New query. Mở tệp supabase/CAI_DAT.sql bằng Notepad hoặc VS Code, sao chép toàn bộ, dán vào SQL Editor rồi chọn Run. Chờ kết quả thành công. Tệp này đã gộp các bước cài đặt.
  3. Mở Table Editor. Kiểm tra có cx_people, cx_threads, cx_messages. Trong Storage kiểm tra hai bucket riêng tư connect-files và documents.
  4. Trong Connect hoặc Project Settings → Data API, sao chép Project URL dạng https://…supabase.co. Trong Project Settings → API Keys, lấy Secret key cho máy chủ. Cả hai phải thuộc cùng dự án vừa chạy SQL.

2. Đưa mã lên GitHub

  1. Trên GitHub chọn New repository, đặt tên mới, ví dụ 115-connect-ksnk. Có thể chọn Private.
  2. Dễ nhất trên Windows: mở GitHub Desktop → File → Clone repository, chọn kho mới, rồi mở thư mục vừa tải về. Chép nội dung trong thư mục đã giải nén vào thư mục kho, gồm package.json, package-lock.json, app, lib, public, supabase và các tệp còn lại. Tệp package.json phải nằm ngay ở gốc kho.
  3. Trở lại GitHub Desktop, ghi Khởi tạo KSNK Ngoại khoa ở Summary, chọn Commit to main → Push origin. Trên GitHub mở kho và kiểm tra đã thấy package.json ở trang đầu. Tệp .env.example chỉ có mẫu trống.

3. Kết nối kho với Vercel

  1. Trong Vercel chọn Add New → Project → Import Git Repository. Chọn kho GitHub mới. Nếu chưa thấy kho riêng tư, mở cấu hình kết nối GitHub và cấp quyền cho đúng kho đó.
  2. Chọn Framework Preset: Next.js, Node.js 24.x, Root Directory là thư mục chứa package.json (mặc định ./ nếu làm theo bước 2). Vercel đọc cấu hình cài đặt và build từ vercel.json.
  3. Mở phần Environment Variables ngay trong màn hình Import. Thêm ba dòng ở bảng dưới vào Production. Nếu dùng Preview, trỏ Preview tới Supabase thử nghiệm và khai báo bộ biến riêng cho Preview.
Tên biến (Key)Giá trị cần điền (Value)
SUPABASE_URLProject URL lấy ở bước 1. Chỉ dán tới .supabase.co.
SUPABASE_SECRET_KEYSecret key của Supabase mới, thường bắt đầu bằng sb_secret_. Nếu dự án chỉ có khóa cũ, dùng tên biến SUPABASE_SERVICE_ROLE_KEY với giá trị service_role. Chọn một loại khóa máy chủ.
BOOTSTRAP_ADMIN_CODETự tạo mã riêng cho lần đăng nhập quản trị đầu tiên, từ 12 ký tự tới 72 byte. Nên dùng trình quản lý mật khẩu để tạo. Tên tài khoản khởi tạo là admin.

Các khóa máy chủ chỉ điền trong Vercel. Tránh đưa vào GitHub, tệp HTML hay các biến bắt đầu bằng NEXT_PUBLIC_. Bản mới lưu phiên phía máy chủ, dùng cookie HttpOnly và kiểm tra tài khoản trong Supabase. Khi nhân bản từ cấu hình cũ, ba biến trong bảng trên là cấu hình đăng nhập của bản mới. APP_DEFAULT_PASSWORD và SESSION_SECRET thuộc cơ chế cũ.

  1. Nhấn Deploy. Khi trạng thái là Ready, mở tên miền mới và thêm /api/health vào cuối. Mong đợi {"ok":true,"supabaseDatabaseReachable":true}.
  2. Để sửa biến sau này: mở đúng dự án mới → Settings → Environment Variables, sửa giá trị, chọn Production, nhấn Save. Vào Deployments, chọn menu … → Redeploy của bản Production. Chờ Ready rồi kiểm tra lại.

4. Đăng nhập và quản trị

Đơn vị đăng nhập là Bệnh viện Ngoại khoa 115 Nghệ An. Dùng tên và mã cá nhân. Ở bản cài mới, đăng nhập bằng admin và mã khởi tạo. Ở bản nâng cấp, dùng mật khẩu admin hiện tại.

Quản trị vào trang nghiệp vụ, chọn Quản trị nhân viên → Danh mục nhân viên hiện tại. Chọn hồ sơ theo mã, tên và bộ phận rồi cấp tên đăng nhập và mã. Có thể khóa tài khoản hoặc cấp lại mã trong cùng mục. Chỉ đánh dấu quyền phụ trách nghiệp vụ cho người được phép sửa sổ nghiệp vụ.

5. Giao việc, nhắc việc và trao đổi

Người phụ trách mở Giao việc & Nhắc việc, chọn loại phiếu, người nhận từ danh mục Ngoại khoa và lưu. Nhân viên đăng nhập vào Nhắc việc để xem việc liên quan và nội dung tin gần nhất. Chọn Mở để đọc, trả lời hoặc gửi ảnh và tài liệu. Các thành viên của việc dùng cùng một cuộc trò chuyện khi mở từ phiếu hoặc từ thông báo.

Khi trang đang mở, ứng dụng kiểm tra tin mới khoảng 12 giây một lần. Bấm thông báo để mở đúng cuộc trò chuyện. Số chưa đọc giảm khi đọc tới cuối khung chat. Bấm Bật chuông để nghe âm trong lúc trang đang hoạt động. Khi trình duyệt đã đóng, tin được lưu cho lần đăng nhập tiếp theo.

Nút Nhắc việc (số phiếu) ở góc trái mở Cảnh báo hôm nay. Chọn Tất cả, Giao việc hoặc Nhắc việc. Mỗi phiếu đang đến hạn, quá hạn hoặc có tin chưa đọc xuất hiện một lần. Bấm thẻ để mở cuộc trao đổi của phiếu. Số trên nút là số phiếu, số tin chưa đọc nằm trên từng thẻ.

6. Nâng cấp tại chỗ

Sao lưu dự án đang vận hành. Thử trên bản sao trước. Chạy toàn bộ supabase/NANG_CAP_TAI_CHO.sql rồi triển khai mã tương ứng. Tập lệnh chuyển tài khoản quản trị khởi tạo tên admin sang Ngoại khoa và yêu cầu đăng nhập lại bằng mật khẩu hiện tại. Dữ liệu cũ của đơn vị khác được giữ trong cơ sở dữ liệu. Kiểm tra bằng hai tài khoản là thành viên của cùng một phiếu.
